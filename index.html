01 · Overview

為什麼選這個訊號？

📖 Part 1

背景故事

先理解 NCKU 平台的遊戲規則，才能想清楚什麼策略才合理。

NCKU 模擬股票交易平台跟現實股市有關鍵幾點不同： 交易不是線上即時撮合，而是每日固定結算── 所以無法當沖。系統也不發股息，長期持有沒有任何被動收益。沒有 0050 這種 「買著不動就會漲」的穩賺選項。

這代表唯一能產生收益的方式只有低買高賣賺取價差。 而平台撮合訂單的條件是：委託價必須落在當日 [low, high] 區間之內， 只要落在裡面，就會 100% 成交（perfect fill）；不在裡面，整筆委託作廢。

這個規則直接給出最合邏輯的策略：每次買單就掛在當日最低點 Lt、 每次賣單就掛在當日最高點 Ht。 中間任何價位（譬如均價、開盤價、收盤價）對我們來說都毫無意義 ── 因為我們可以保證掛在 L 跟 H 上一定會 fill，那為什麼要掛在中間賺更少？

🎯 Part 2

核心交易策略

把賺價差的邏輯推到極致：今天買、隔天賣、強制脫手。

很明顯：若只能透過「買 L、賣 H」賺價差，最快的賺錢策略就是 今天買、隔天馬上賣。問題就可以乾淨地定義成一個機器學習任務：

🧮 問題定義

給定第 t 日所有候選股票的歷史 OHLC， 為每一檔 i 預測：

yi,t  =  log ( Hi,t+1 / Li,t )

然後選 y 預測值最大的 K = 5 檔，今天 13:00 前掛 limit buy @ Lt、 隔天 13:00 前掛 limit sell @ Ht+1。每檔分配 1/5 資金，等權重。

這個策略最重要的特徵不是「買 L 賣 H」── 而是 「隔天賣是強制的」。 無論隔天是漲是跌、無論還想不想留，通通在隔日盤中 以 limit sell @ floor_tick(Ht+1 − 1tk) 全部出清， 當天再用變回現金的資金重新買今天的新 5 檔。為什麼一定要強制？三個理由：

🔄
資金週轉率拉到極限

每個交易日完成「進 → 出 → 再進」的完整循環，N 個交易日就有 N 次複利機會。 如果改成持有 2 天，cycle 數量直接砍半，複利威力縮水。

🛡️
每天 reset 一次曝險

股票過夜會吃到下個交易日的開盤跳空、消息面、大盤系統性風險。 強制隔日脫手 = 最大持倉時間 1 個交易日，風險不會跨日累積。

🎯
問題形式最簡單

因為 target 直接定義在 (t, t+1) 這一對價格上，模型每天獨立判斷 24 小時內的反彈強度，不需要做多步動態規劃 ── 變成 ML 上熟悉的「每日截面排序」問題。

整理一下完整策略，每天的工作流程：

  1. 早上模型預測：把 1900 多檔股票丟進 LGBM 算分數，估計每檔的 yi,t。
  2. 過濾：踢掉流動性不足、價格過低、今日漲停的股票。
  3. 選 K = 5：分數最高的 5 檔。
  4. 建立兩組訂單：(a) 把昨天的 5 檔以 Ht−1tk 全部 sell；(b) 把今天新的 5 檔以 Lt+1tk 各買 20% 資金。
  5. 13:00 前送進 NCKU API，下班，等明天再來一輪。

後面的章節會進入細節：模型怎麼學排序（§02 數學形式 + §04 設計取捨）、 架構怎麼跑（§03）、每個特徵在學什麼（§05）、K 為什麼是 5（§06）、 模型 vs 隨機的對照（§07）、評估方法 + 結果（§08–09）、實盤怎麼下單（§10–11）。

02 · Mathematical Formulation

用數學描述整套策略。

整個策略可以拆成四個數學物件：學習目標（要預測什麼）、 損失函數（怎麼訓練）、 評估指標（怎麼判斷模型好壞）、 投組構造（怎麼把預測變成下單）。 下面四張卡分別解釋這四件事，順著讀就是完整訓練 → 推論 → 執行的數學鏈條。

Target

① 學習目標：要預測什麼

給定第 t 日股票 i 的 OHLC（Open / High / Low / Close 四個價格）， 我們要預測的是「明日最高 Hi,t+1 相對今日最低 Li,t 的對數成長率」：

yi,t  =  log Hi,t+1Li,t

直觀解讀：如果我們今天能買在 Lt、明天能賣在 Ht+1， 這筆交易的對數收益是多少。取 log 而非簡單百分比，是為了讓正負對稱（log(H/L) ≈ (H-L)/L 在小範圍內等價，但 log 在 cross-section 排序時有更穩定的尾部）。

重點：Lt 在當日 13:00 前已透過 TWSE 即時 API 揭露， 所以模型在「今天結束、明天開盤前」做預測時，Lt 是可用資訊， 不算未來函數。

Loss

② 損失函數：LambdaRank

每天把該日所有股票的 yi,t 排序，分成 10 個十分位數 ℓi,t ∈ {0,…,9}， 0 是最差（明日反彈最弱），9 是最好。模型訓練時不直接逼近 yi,t， 而是學「兩兩比較」── 給定股票對 (i, j)，模型要學會 哪一檔的 ℓ 較高：

L  =  Σt Σ(i,j)∈Pt  |ΔNDCG(5)ij| · log(1 + e−σ(si−sj))

逐項拆解：si 是模型給股票 i 的分數（無單位）， Pt 是該日所有「label 不同」的股票對， |ΔNDCG(5)| 是「如果把這對 i, j 互換位置，NDCG@5 會變化多少」的絕對值。

意義：每對股票的損失大小，被「換它們會不會影響 Top-5 排名」加權。 換言之，排錯前 5 名的成本最大、排錯後段（譬如第 200 vs 第 250 名）幾乎不影響梯度。 這正是我們要的：模型只需要把前 5 名挑準，後段順序隨意。

Metric

③ 評估指標：NDCG@5

NDCG@K（Normalized Discounted Cumulative Gain）來自資訊檢索領域， 原本用來評估搜尋引擎的前 K 個結果排得好不好。在我們的場景裡， 它衡量「模型挑出的前 5 檔，相比理想答案差多少」：

NDCG@K  =  1ZK  ΣKr=1  2ℓ(r) − 1log2(r + 1)

公式裡 ℓ(r) 是模型排序第 r 名（r=1 表示首選）股票的真實 label。 分子 2ℓ − 1 對 high-label 給指數獎勵 （label 9 比 label 0 多得 511 倍分數）； 分母 log2(r+1) 對「排得越後面」給折扣。 ZK 是理想排序下這個量的最大值， 除以它讓 NDCG ∈ [0, 1]。

➜ 1.0 = 完美排序，0.5 ≈ 隨機排序。LambdaRank 的損失函數梯度同時和這個指標耦合， 所以它字面上就是在「沿著最大化 NDCG@5 的方向」優化。

Portfolio

④ 投組構造：把分數變成下單

模型 inference 完得到分數矩陣後，每日從合格池 Ft （後文會解釋這個過濾條件）裡取分數最高的 K=5 檔：

St  =  argmax|S|=K, S⊆Ft  Σi∈S  si,t

每檔等權重持有 wi = 1/K = 20%。 當日含交易成本的單日報酬可寫為：

rt  =  1K  Σi∈St  [  H↓i,t+1L↑i,t  (1 − cs)(1 − cb) − 1 ]

注解：L↑ 表示「把 L 向上取到合法 tick」（買單規則，後段詳述）， H↓ 是賣單向下取。 cb = 0.1425% 是買方手續費，cs = 0.4425% 是賣方手續 + 證交稅， 兩者相乘就是來回交易成本約 0.585%。

Filter Set

合格池 Ft：哪些股票才能被選

前面公式裡的 Ft（合格池）不是「全部 1957 檔」，而是經過三重條件過濾後的子集合。 這三條過濾不是任意設的，每一條都對應一個現實 / 統計問題：

① 流動性
ADV20(i, t) ≥ 5×107
20 日平均成交金額至少 5000 萬 NTD。
為何：成交太冷的股票，我們的買單可能撐起價格、賣單可能撈不到買盤。 模擬平台會 perfect-fill，但實盤會有滑點，這條過濾預先排除了最危險的標的。
② 下限價
Ci,t ≥ 10
收盤價至少 10 元。
為何：< 10 元的股票 tick = 0.01，但相對價格只有 0.1%； 而 ≥ 10 元的股票 tick = 0.05，相對 0.5%。低價股的「±1 tick margin」相對成本太大， 訊號比較 noisy。
③ 避漲停
(Ct − Ct−1) / Ct−1 < 0.07
今日漲幅 < 7%（台股漲停板是 ±10%）。
為何：今日已接近漲停的股票，明日繼續上攻的空間先天受限， 而且容易出現「跳空高開後一路殺低」的不利型態。先避開。
03 · Architecture

資料怎麼從原料變成下單。

下圖完整呈現「每天 13:00 截單前要跑一次」的線上推論流程 （training 是 offline 一次性的事情，這裡先省略，模型就當作已經訓練好放在 disk 上）。 整個流程分成 10 個 Phase，每個 phase 都是一個明確的處理步驟， ~1957 檔候選股票會依序穿過所有 phase，最後變成 NCKU API 收到的買賣單。

流程的整體骨架是這樣：先收三路資料（Phase 01）→ 統一存到 parquet（Phase 02）→ 生 20 個技術特徵（Phase 03）→ 打包成 3D tensor（Phase 04）→ 丟進 LGBM 算分數（Phase 05–06）→ 三條件過濾掉不合格股票（Phase 07）→ 取分數最高的 5 檔（Phase 08）→ 為每檔生 1 sell + 1 buy 訂單（Phase 09）→ 送進 NCKU 平台（Phase 10）。

其中 Phase 08（Top-K 選股）是策略的「決策點」── 在這之前是 純資料處理，在這之後是 執行邏輯。Phase 08 之後流程從一條變成兩條： 玫紅色的 SELL 路徑（賣昨日持倉）+ 藍色的 BUY 路徑（買今日新單）， 最後在 Phase 10 合流到 NCKU Trading API。 色彩編碼：藍 = 資料 / 主流程、綠 = 資料源 / 選股、 橘 = 過濾、玫紅 = 賣方、深灰 = 模型 / 終端。

逐 Phase 解說

把 10 個 phase 分成四個邏輯區塊講，每塊解釋它在做什麼、為什麼存在、技術細節是什麼。

Phase 01–02 · 資料收集 + 統一儲存

資料分三路收：

  • yfinance batch：每天 ~15:30 後跑 update_parquet.py，抓昨日全市場 OHLCV 並寫入 parquet。
  • TWSE MIS API：實盤當天跑 inference 時，從台股即時 API 拿 intraday L/H/C（這樣才能在 13:00 前知道今日 Lt）。
  • KMeans 概念股分群：預先算好的 .npz 靜態檔，提供「相對於同概念股的動量」這個特徵的對照基準。

全部塞進同一個 all_stocks.parquet， 列式儲存方便後續高效切片（1957 codes × 1533 days）。

Phase 03–04 · 特徵工程 + 打包

20 個特徵分成 5 個族群（每個族群解釋不同市場行為）：

  • Momentum × 6：5/10/20/60/120 日對數動能 + 同概念股相對動能。
  • Range / Vol × 5：日內振幅、ATR、Garman-Klass、body-proportion 等波動指標。
  • OHLC Lag × 4：今日 / 前日對昨收的對數變化（含最強訊號 dn_lag0）。
  • Liquidity × 2：log_adv（成交額）、Amihud illiquidity。
  • Cross-Section Rank × 3：當日截面 percentile rank。

全部打包成 3D tensor X ∈ ℝ(D×N×20)，一次性載入記憶體。

Phase 05–06 · 模型推論

LGBM Booster 一次性 inference 整個 (D × N × 20) 張量，輸出分數矩陣 S ∈ ℝ(D×N)。 LightGBM 對缺失值（NaN）原生友善，所以某些特徵在某些日期 / 個股缺失也不影響結果。 整個過程 < 1 秒（因為樹模型的 inference 是常數時間查表，不像 Transformer 要過好幾層 attention）。 這個分數沒有單位、不是「明天會漲幾 %」，純粹是「相對排序的依據」。

Phase 07 · 過濾（合格池）

有了分數還不能直接選 Top-5，要先把「不適合下單」的股票剔除：

  • ADV20 ≥ 5×107（沒流動性的不能買）
  • Ct ≥ 10（penny stock 的 tick 相對誤差太大）
  • 當日漲幅 < 7%（避開漲停）

三條都通過才進入合格池 Ft，三條都是 AND 關係。

Phase 08–10 · 選股 → 訂單分流 → 送單

這是策略的「執行端」。Phase 08 從合格池裡 argsort 取分數最高的 5 檔，這就是今天要買的清單。 接著流程分裂成兩條並行路徑：

💸 SELL Side（玫紅）

把昨天買的 5 檔全部出清， 掛單 @ floor_tick(Ht − 1 tick)。 這是強制脫手，無論漲跌都要賣。

💵 BUY Side（藍）

把今天 Phase 08 選出來的 5 檔各買 1/5 資金， 掛單 @ ceil_tick(Lt + 1 tick)。

兩條路徑的訂單最後在 Phase 10 同時送到 NCKU API，13:00 截單、15:30 結算、16:00 公告結果。 每個工作日重複一次。

04 · Key Decisions

六個關鍵設計取捨。

設計這套策略時，每個技術選項背後都有別的選項可以選。下面六張卡記錄了 為什麼最後選現在這個版本， 每個決定都是試錯後留下的結果，不是憑空寫出來的。

Choice 1

為何用 LightGBM 而不是 Transformer？

一開始是用 DSPO Transformer 試 spread 預測，但短週期股價訊號雜訊極多， 深度模型很容易 overfit 在訓練期。LightGBM 三大優勢正好對到我們的痛點： (1) 對缺失值 NaN 原生友善，特徵生成不需要 imputation； (2) 全市場 1957 檔 × 600 天的 inference 整個跑完 < 1 秒，比 Transformer 快一個數量級； (3) 樹模型本身有正則化（min_child_samples、bagging），對 noisy data 比較穩健。

Choice 2

為何用 LambdaRank 而不是回歸 (regression)？

MSE 回歸會把預測精度的力氣分散在「全市場每一檔股票」上。 但實際下單只挑 Top-5，後 1900 多檔的預測準不準根本無關緊要。 LambdaRank 把訓練梯度集中在「兩兩比較哪個排名更前」， 再透過 truncation_level=5 把 NDCG 截斷在前 5 名 ── 字面意思就是「梯度反向傳播時，只有 會影響到 Top-5 名單的錯誤才會被懲罰」。 這是把 loss function 跟業務目標完美對齊。

Choice 3

為何回測時間對齊用 Setup B？

常見的回測對齊有兩種：A 是「用昨日特徵預測今日」，B 是「用今日特徵（含 Lt）預測明日 Ht+1」。 很多人會直覺選 A 以為比較保守，但對我們的 setup 反而是錯的── NCKU 平台 13:00 前才下單，那時 today's intraday low 已經透過 API 揭露，是合法可用資訊。 選 B 才能真實反映實盤可取用的訊號。回測程式裡 signal_idx = today_idx 即是這個對齊。

Choice 4

為何最後選 K = 5（而不是更小或更大）？

我們系統性掃了 K = 1, 2, 3, 5, 7, 10, 15, 20, 30, 50, 100 共 11 種選擇（後段 §06 詳細）。 K=2 報酬最高（+16.74% / cycle）但只有 2 檔分散，單檔失敗影響大； K=7 Sharpe 最高 (97.79) 但報酬比 K=5 略低； K=5 在報酬與 Sharpe 兩個指標都進入前 4 名， 而且 5 檔分散度合理、單檔影響可控，是穩健折衷。

Choice 5

為何把特徵從 43 個砍到 20 個？

初版用 43 個特徵（涵蓋短中長期動量、振幅、流動性、季節性等等）。 訓練好後看 LGBM 的 gain importance ── 發現 前 20 個特徵已經占整體 gain 的 99%+， 後 23 個幾乎沒貢獻。乾脆砍掉，換得：訓練速度快一倍、推論更穩定、減少 overfit 風險。 砍完後在 holdout 期 NDCG 不降反升，證實這 23 個是雜訊不是訊號。

Choice 6

為何實盤要加 ±1 tick margin？

NCKU 平台規則：委託價必須落在當日 [L, H] 區間才會 fill。 如果掛在剛好的 Lt，遇到雜訊或撮合順序問題就可能 miss。 所以實盤改成「買價 = Lt + 1 tick」、「賣價 = Ht+1 − 1 tick」── 犧牲一點 spread 換取 fill rate。tick 大小依 TWSE 規則隨價格區間變化（0.01~5.00）， 程式內用 snap-to-tick 函式自動處理。

05 · Feature Importance

模型到底在學什麼？

LightGBM 訓練完後，每個特徵會記錄一個 gain 數值 ── 代表「這個特徵在所有決策樹中被拿來分裂節點時，總共降低了多少 loss」。 把所有特徵的 gain 加總正規化後，就得到下圖每個特徵的「相對重要性百分比」。

結果出乎意料地集中：前 3 個特徵承擔了 85.43% 的 gain， 其中 dn_lag0 一個就拿走 52.77%。 換言之，模型很大程度上是在學「今天跌得多深」這件事 ── 這也直接驗證了 「跌深反彈」是這個策略的主要 alpha 來源。

前 3 個特徵的細節

既然這三個特徵承擔了 85% 的解釋力，值得仔細看看每個是什麼、為什麼重要。 三個都是「日內價格行為」相關，符合「跌深反彈」這個 alpha 的物理直覺： 模型靠看今日跌幅 + 今日報酬 + 振幅 percentile 三個訊號就能定位反彈標的。

06 · K Sweep

該選幾檔？分散 vs 集中。

LGBM 排出分數後，每天要選前幾名來買，這個「幾名」就是超參數 K。 理論上 K 越小報酬越高（只挑最好的 1~2 檔來重壓）， 但 K 越小分散度越差、單檔失敗影響越大。為了找出最佳折衷點， 我們把 K 當作可掃描的超參數來實驗。

在 2026-01 ~ 2026-04 區間，用 cumulative_walkforward backtest（每日 diff-based 再平衡） 跑 11 個 K 值（1, 2, 3, 5, 7, 10, 15, 20, 30, 50, 100）。 評估指標除了總報酬，更重要的是 cycle return── 單日複利報酬的幾何平均（換算公式 cycle = (1 + total)1/N − 1， N ≈ 84 個交易日），代表「平均每天賺幾 %」。 之所以看 cycle 而不只看總報酬，是因為總報酬會被 N 倍複利放大到誇張的數字（譬如 K=1 總報酬達 360 萬 %）， cycle return 才能公平比較不同 K 值的單期生產力。

Cycle return = (1 + total_return)1/Ncycles − 1，Ncycles ≈ 84 個交易日。 K 越小報酬越高但變異也大；K=2 雖最高但只有 2 檔分散，單檔下單失敗會大幅影響。K=5 取折衷。

07 · Baseline Comparison

LGBM 真的有貢獻嗎？對照組驗證。

LGBM 4 個月平均 +267% 看起來很驚人，但這個數字有個盲點： 如果這個策略本身（買今日 L、賣明日 H、每日全脫手）就有偏誤， 那麼即使隨便挑 5 檔來買也會賺，LGBM 只是錦上添花。 我們需要驗證：LGBM 真的有貢獻，而不只是搭順風車。

做法：保留所有條件不變（K=5、買賣邏輯、過濾池、結算引擎），只把 「LGBM 排序 Top-5」換成「從合格池均勻隨機抽 5 檔」， 其他完全一樣。如此一來兩組的差異就是 LGBM 排序的純貢獻。 隨機選股會因種子而變，所以每月跑 30 個 seeds 取分佈，再用 z-score 衡量 LGBM 比 random 好多少標準差。

兩個關鍵發現

把實驗組（LGBM）跟對照組（random）一比，可以同時得到兩個對策略理解極為重要的洞察： 既揭露了模擬平台的「天然偏誤」，也定量了 LGBM 模型的「真實 alpha」。

!

發現 1：策略本身就有偏誤

隨機選股 4 個月平均也賺 +118%。 這個數字嚇人 ── 它說明「買 Lt → 賣 Ht+1」這個策略本身， 在 NCKU rule_game 的 perfect-fill 假設下天然有正期望值，連抽籤都能贏。

原因：模擬平台假設「只要委託價落在 [L, H] 就 100% 成交」。 現實中，要剛好掛在 L 買到、剛好掛在 H 賣出，幾乎不可能。 所以這個 +118% 是「上限」，實盤會被滑點 / 未成交 / 部分成交大幅縮水。

✓

發現 2：LGBM 的真實 alpha

LGBM 比 random 平均多 +148.96pp， 四個月 z-score 全部 ≥ 7σ（最高 14σ）。在統計上， 這代表「LGBM 不是運氣好抽到好月份，是系統性贏過 random」。

意義：這個 +148.96pp 才是「模型」的真實價值。它對應的是 LGBM 排出的 Top-5 相比隨機 5 檔的 spread 差異 ── 這部分相對穩固，因為實盤即使部分成交， 排得好的 5 檔仍系統性勝過隨機 5 檔。

把總報酬拆成兩部份

平均來看，LGBM 的 +267% 報酬可以拆解為「策略本身的 perfect-fill 偏誤」 + 「LGBM 排序帶來的 alpha」：

策略偏誤 +118%
LGBM 排序 alpha +149pp
0% +267% 平均總報酬

實盤上線時，紅色「策略偏誤」會因為 fill rate < 100% 而大幅縮水（限價單可能掛不到 Lt 那麼低）。 藍色「LGBM 排序 alpha」相對穩固，因為 fill rate 受影響的是「成交與否」而非「排序好壞」。

08 · Evaluation Methodology

怎麼判斷模型有沒有真的學到東西？

機器學習最大的陷阱是「模型在訓練資料看起來很神，上線後變廢」。 原因常常是 leakage（資料洩漏）、overfit（過擬合）或評估指標選錯。 為了避免，我們把所有資料分成三段時間區間， 每段角色不同；模型只看得到該看的區間，整個流程做到完全 out-of-sample。

時間軸切割：訓練 / 驗證 / 驗收

2020-04 到 2026-04 大約 6.2 年資料，按時間順序切成三段。 早期占比最大（給模型學歷史 pattern），中期是調參驗證期，最近期保留給最終驗收。

TRAIN
2020-04-01 ~ 2025-06-30
~5.2 年 · 1300 個交易日
VAL (OOS)
2025-08 ~ 2026-03
8 個月 · early-stop & K sweep
UPLOAD
2026-01 ~ 04
NCKU 平台 4 個月驗收

TRAIN 與 VAL 之間留 1 個月 gap（2025-07）避免 leakage；UPLOAD 期完全 OOS， 模型訓練時看不到任何 2025-08 之後的資料。

每階段的目的與指標

三階段不只是時間切割，三者的「角色」也完全不同： 訓練期確保模型有收斂，驗證期決定超參數，驗收期判定最終效果。 指標也分層使用，避免「為了通過某個指標而 overfit 到該指標」：

1

Training（訓練期）

目的：讓 LGBM 真的學到東西、判斷是否收斂。

指標：LambdaRank loss、in-sample NDCG@5。 訓練時用 validation NDCG 做 early-stop（patience=50 棵樹）， loss 不再下降就停，避免 overfit。

2

Validation（驗證期）

目的：選超參數（K、學習率、num_leaves 等），但不能影響模型權重。

指標：local rule_game backtest 的 total_return、Sharpe、max_dd、fill_rate。 K sweep 就是在此期完成、挑出 K=5。

3

Upload（最終驗收）

目的：把最終版策略丟到 NCKU 官方平台，看真實結算結果。

指標：平台給的 total_return、final_assets。 每月獨立上傳（避免複利 N 倍掩蓋真實 cycle 績效）， 結果是不可逆的 ground truth。

下單細節：tick 規則與成本。

預測模型再準，實盤要賺錢還得真的「下得進去」+「成本算對」。 這節整理兩個容易被忽略卻會把績效啃光的細節： TWSE 跳動單位 (tick) 規則 （委託價要剛好落在合法 tick 上，不然會被自動調整）、 以及浮點誤差 (FP precision) （Python 內 16.90/0.05 不等於整數 338，會出 bug）。 最後也列出買賣雙邊的真實交易成本，回測時一定要扣。

snap-to-tick：避免 FP 浮點誤差

發現 16.90 / 0.05 在 IEEE 754 變成 337.999... 導致 floor 錯誤。 先 snap 到合法 tick 再加減才安全：

tick_up(p, n)  =  round( round(p / τ) · τ,  4 )  +  n · τ 
# live_trade_lgbm.py / my_strategy_lgbm.py
def _tick_size(p):
    if p < 10:    return 0.01
    if p < 50:    return 0.05
    if p < 100:   return 0.10
    if p < 500:   return 0.50
    if p < 1000:  return 1.00
    return 5.00

def tick_up(p, n=1):
    t = _tick_size(p)
    snapped = round(round(p / t) * t, 4)
    return round(snapped + n * t, 4)

def tick_down(p, n=1):
    t = _tick_size(p)
    snapped = round(round(p / t) * t, 4)
    return round(snapped - n * t, 4)
